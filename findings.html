Findings → decisions

Each row reads left to right: what we found, where we found it, what we'll do about it and how we'll know if it worked.

Every check is labeled Planned until it has actually been done. When a check is done, we'll change the label, add the date and link the evidence.

Each finding traced to its source, the decision it leads to and how we'll check it
#FindingSourceProposed feature or design decisionHow we'll check it
F1 Evidence Starter Story and MicroConf lead with social proof: counts (“4,082+ real, revenue-generating projects,” “12,568 builders building”) and testimonial walls. S1, S2, S3, S4 Use social proof only when it can be checked: real, linked examples, never anonymous testimonials. Planned A reviewer opens every example on the future guide and confirms it links to a public source.
F2 Evidence MicroConf Connect costs $49/month or $499/year and requires an application. S4 Keep the core “start here” path free, with no signup required to read it. Planned Ask 5+ students whether price would stop them from joining a paid founder community.
F3 Evidence On the four pages captured, no path was aimed specifically at students. Assumption We assume this holds more widely. S1–S4 Make a “Student start here” page the main entry point of the guide. Planned Check Indie Hackers and 2 more sites for a student path. Five-second test with 3 classmates: can they tell who the guide is for?
F4 Evidence Starter Story shows revenue figures (e.g. “$40K/mo”) prominently. Analysis We did not see how they are verified on these pages. S1 Label every revenue figure “verified” or “self-reported,” with its source. Planned Audit: every number on the guide has a label and a link.
